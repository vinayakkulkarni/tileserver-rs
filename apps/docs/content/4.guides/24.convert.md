---
title: Converting GeoJSON/CSV to PMTiles
description: Turn a single GeoJSON or CSV file into a PMTiles vector-tile archive with the built-in `tileserver-rs convert` subcommand — pure Rust, no tippecanoe, optional instant serving.
---

`tileserver-rs convert` turns a GeoJSON or CSV file into a [PMTiles](https://github.com/protomaps/PMTiles) archive of MVT (Mapbox Vector Tile) tiles. It is a pure-Rust pipeline — no tippecanoe, no GDAL — aimed at small and medium single-file conversions (city, region, or country extracts).

```bash
tileserver-rs convert input.geojson --output out.pmtiles
```

Enable the feature at build time (it is **not** in the default build):

```bash
cargo build --release --features convert
```

## When to use what

| Workload | Tool |
|---|---|
| A single GeoJSON or CSV under ~1 GiB — city, region, or country extract | **`tileserver-rs convert`** (this guide) |
| Planet-scale input (OSM PBF, Overture Maps, multi-GB) or deep tippecanoe feature parity | [tippecanoe](https://github.com/felt/tippecanoe) |

When the input file is larger than 1 GiB, `convert` prints a hint pointing at a dedicated planet-scale builder — the pipeline still runs, but a purpose-built tool will be dramatically faster.

## GeoJSON

```bash
tileserver-rs convert cities.geojson --output cities.pmtiles
```

- Input coordinates are assumed to be **WGS84 (EPSG:4326)** lon/lat.
- Output tiles are **Web Mercator (EPSG:3857)**, as the MVT spec requires.
- Feature IDs are auto-detected from `id`, `gid`, `ogc_fid`, or `OBJECTID` (in that order, case-insensitively). Override with `--id-property`.

## CSV

CSV inputs need a geometry source. Two modes:

**Latitude / longitude columns** (synthesizes POINT geometry):

```bash
tileserver-rs convert cities.csv \
  --lat latitude --lng longitude \
  --output cities.pmtiles
```

**WKT geometry column** (auto-detected from `geometry`, `wkt`, `geom`, or `shape`, or set explicitly):

```bash
tileserver-rs convert regions.csv \
  --geometry-column wkt \
  --output regions.pmtiles
```

CSV cell values are type-inferred: `true`/`false` become booleans, integers and floats are parsed as numbers, everything else stays a string. Rows whose WKT fails to parse are skipped with a warning rather than aborting the run.

## Zoom range and simplification

```bash
tileserver-rs convert input.geojson \
  --min-zoom 0 --max-zoom 14 \
  --output out.pmtiles
```

- `--min-zoom` / `--max-zoom` default to `0` and `14`.
- `--auto-max-zoom` picks a max zoom from data density, capped at 14.
- Geometries are simplified per zoom with Douglas-Peucker using a tippecanoe-style tolerance (`4.0 / 2^(z - min_zoom)`, floored at `0.5`). Override the tolerance with `--simplification`.
- `--drop-densest` (on by default) caps very dense tiles at 1000 features.

## Properties and layer name

```bash
tileserver-rs convert input.geojson \
  --layer-name places \
  --include-properties name,population \
  --output out.pmtiles
```

- `--layer-name` sets the single output MVT layer name (defaults to the input filename stem).
- `--include-properties` is a whitelist; `--exclude-properties` is a blacklist. The whitelist wins when both are set.

## Serve the result immediately

```bash
tileserver-rs convert cities.csv \
  --lat latitude --lng longitude \
  --serve --port 8080
```

`--serve` writes the archive (to a temp path when `--output` is omitted) and boots the HTTP server pointed at it, reusing the standard server startup. The tiles are then available at `/data/{layer}/{z}/{x}/{y}.pbf` with TileJSON at `/data/{layer}.json`.

## Out of scope

- HTTP conversion endpoint (`POST /api/convert`) — deferred.
- Shapefile / FlatGeobuf / KML / GPX input — future work.
- Reprojection — input is assumed WGS84.
- Multiple output layers per call — single layer only.
- MLT output — `convert` emits MVT; use the [`mlt`](/guides/mlt) feature to transcode downstream.
